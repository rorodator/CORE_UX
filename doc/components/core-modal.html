<core-modal> slot event

Dialog overlay. Toggle with the open attribute (or property / show()). Backdrop, ×, Escape, and author close controls request a close that the page may deny.

Backdrop: --core-color-overlay. Panel: --core-color-surface, --core-shadow-lg. Theming reference
Attribute / patternValuesDescription
openbooleanShow / hide dialog. Reflected by the open property. Removing it closes unconditionally (no close event).
titlestringDialog title (aria-labelledby). Updated in place while open.
aria-labelstringAccessible name when no visible title is provided.
sizesm · lg · fullWidth modifier. Updated in place while open.
data-core-footer—Footer slot (same as card).
data-core-initial-focus— (on a descendant)Explicit opening focus target. On a wrapper (e.g. <core-field>, <core-button>) its first focusable descendant is used; tabindex="-1" static elements are accepted. Disabled or hidden targets are skipped.
data-core-modal-close— (on a descendant)Clicking the element requests a close with reason close (used by the header ×; also for footer “Cancel” buttons).

Events

EventdetailWhen
core-modal-request-close{ reason }Before a requested close (Escape, backdrop, ×, data-core-modal-close, requestClose()). Bubbles, cancelable: call preventDefault() synchronously to keep the modal open.
core-modal-close{ reason }After a requested close actually happened (open already removed). Bubbles, not cancelable. Not dispatched for denied requests, close(), open = false, or attribute removal.

reason: escape · backdrop · close (× or data-core-modal-close) · request (default for requestClose()) · any string passed to requestClose(reason).

Public API

MemberReturnsDescription
open (property)booleanGet / set; reflects the open attribute.
show()voidOpens the modal (same as setting open).
close()voidCloses unconditionally and silently (same as removing open). Use after a confirmed operation; focus is restored.
requestClose(reason = 'request')booleanSame path as a user dismissal: dispatches core-modal-request-close, then closes and dispatches core-modal-close unless prevented. Returns true when the modal closed.

Focus policy

Provide either a non-empty title or aria-label; an unnamed dialog emits a console warning and no visible fallback text is invented. The dialog carries role="dialog" and aria-modal="true".

On the closed-to-open transition the modal remembers the active element and focuses, in order:

  1. the first available [data-core-initial-focus] target;
  2. otherwise the first enabled, editable field of the body (input except button-like/hidden types, select, textarea, contenteditable; read-only fields are skipped);
  3. otherwise the dialog itself (tabindex="-1"), so screen readers announce its name and the next Tab reaches the first control.

Buttons and links are never chosen implicitly, so a confirmation never pre-focuses its destructive action — mark the safe action (e.g. Cancel) with data-core-initial-focus when you want it focused. Tab / Shift+Tab stay inside the dialog (including contenteditable editors). Re-setting open, title, or size while open does not move focus or rebuild slotted content. On close, focus returns to the pre-open element when it is still connected and focusable.

Closing policy

Escape, a backdrop click, the header ×, any [data-core-modal-close] control, and requestClose() first dispatch the cancelable core-modal-request-close. Calling preventDefault() (e.g. while a critical save is pending) keeps the modal open, keeps the focus trap active, does not restore focus, does not dispatch core-modal-close, and moves focus back inside if the gesture moved it out. Once the operation succeeds, close programmatically with close() (or by removing open), which is never blocked.

Escape is left to inner widgets that already handled it (preventDefault()), e.g. an open core-menu, core-multi-select, or core-autocomplete list closes first; the next Escape requests the modal close. When several overlays are open, Escape and Tab / Shift+Tab reach only the innermost overlay that owns focus. The kit applies no busy state of its own: show progress on the triggering action and decide in the event listener which reasons to deny.

Blocking close during a critical operation

Click Save, then try Escape, ×, backdrop, or Cancel while saving.
 
let saving = false;
modal.addEventListener('core-modal-request-close', (e) => {
  if (saving) e.preventDefault(); // Escape / backdrop / × / Cancel denied
});

async function save() {
  saving = true;
  try {
    await api.save();
    modal.close(); // never blocked
  } finally {
    saving = false;
  }
}
