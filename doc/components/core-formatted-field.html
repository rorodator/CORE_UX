<core-formatted-field>

Opt-in text field for exact integers, decimals, dates, times, and datetimes. Shared form attrs. This is not a date picker and not a clock popup: the user types text. core-field type="number" and type="date" stay native and unchanged.

The inner control is always type="text". While typing, the raw text is kept (including an incomplete 12, or -). On blur, a valid value is rewritten to the display format and the value attribute becomes the canonical string. An invalid or incomplete value stays as typed, the value attribute is removed, and a .core-error-text with data-core-parse-error shows the raw parser message. A parent error attribute wins over that message. Setting value from script does not emit an event and does not move the caret while the field is focused.
AttributeValues / defaultDescription
value-typedecimal · integer · date · time · datetime · relative-dateDefault decimal. relative-date is the symbolic preset (today, this-month, last-n-days, next-n-days), not a resolved calendar range.
localeen · frDefault en (group ,, decimal .). fr groups with a no-break space and uses , as the decimal separator. A canonical 1.5 is still accepted in fr.
decimal-separator / group-separatorone characterOverride the locale separators. Omit them to keep the locale default.
max-fraction-digitsinteger ≥ 0Validation only. Extra digits are rejected (E_PRECISION) and the full string is kept in errors[].details.exact. Nothing is rounded or truncated.
excess-precisionreject · keepDefault reject. keep accepts the full fraction.
fraction-digitsinteger ≥ 0Time only. The fractional seconds must match this length, or the value is invalid.
formattoken stringDisplay pattern. Defaults: date dd MMM yyyy (English month names, 02 Nov 2026), time HH:mm:ss, local datetime dd MMM yyyy HH:mm:ss, offset datetime the same plus xxx.
temporallocal · offsetDatetime only. Default local (YYYY-MM-DDTHH:mm:ss, no zone). offset requires Z or ±HH:mm. Mixing the two is E_TEMPORAL_MIX.
valuecanonical stringInteger and decimal are digit strings, never JS numbers. Date YYYY-MM-DD. Time HH:mm:ss. A relative date is JSON.
Plus shared form attributes. The input stays type="text".

Date, time, datetime

Month names are the fixed English abbreviations Jan–Dec. There is no calendar popup.

<core-formatted-field label="Date" value-type="date" value="2026-11-02"></core-formatted-field>
<core-formatted-field label="Time" value-type="time" value="14:35:08"></core-formatted-field>
<core-formatted-field label="Local datetime" value-type="datetime" temporal="local" value="2026-11-02T14:35:08"></core-formatted-field>
<core-formatted-field label="Offset datetime" value-type="datetime" temporal="offset" value="2026-11-02T12:35:08Z"></core-formatted-field>
<core-formatted-field label="Relative" value-type="relative-date" value='{"preset":"last-n-days","amount":7}'></core-formatted-field>
