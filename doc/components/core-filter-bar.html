<core-filter-bar>

Inline filters composed from the catalog picker and existing editors. The element creates a filter engine in configure() and exposes the same methods, state$, and events$. It does not load data. The minimal catalog, formats, option provider, and parent subscriber are on Filter bar examples.

A usual type needs no callback: the label, operators, and editor are inferred. User actions are stamped user. destroy() ends the streams and aborts option requests. Removing the element from the page does not. After a catalog choice, focus moves into the new editor. Layout is wrap unless ui.layout or the layout attribute is scroll or vertical.
AttributeValues / defaultDescription
layoutwrap · scroll · verticalOverrides ui.layout for display. Default wrap.
disabledbooleanDisables every editor.

API

configure(config) builds the engine. The element then delegates getDefinitions, getState, getCriteria, getResolvedConfig, validate, exportState, importState, addDefinition, updateDefinition, removeDefinition, addFilter, removeFilter, clearFilter, setValue, setOperator, moveFilter, setPinned, setFilters, reset, transaction, and destroy. state$ replays the current state. events$ stays quiet until a change. validate() reveals errors when validation mode is manual.

There is no filter-added DOM event. Subscribe to events$. A registered editor is extensions.registry.editors[editorRef], a function of the definition that returns { mount, update, focus, destroy }. mount and update must not emit a value change.

Keyboard and touch

Each row has Earlier and Later buttons, and the reorder handle accepts arrow keys inside the pinned or unpinned group. The handle can also be dragged. A pinned filter that the configuration locked cannot be unpinned from the row. Clear empties the value. Remove deletes the instance when it is removable. Is empty and Is not empty hide Clear.
